# 외부 연동 계층 구성

## 폴더·레이어 구조

- 외부 API 연동 코드는 연동 폴더(src/integration) 하위에 연동별 폴더로 둠 — 토스증권은 토스인베스트 폴더(toss-invest)로 정의함
- 연동 폴더는 전송 계층(client/)과 토스 문서 태그별 API 클래스 계층(api/)으로 나눔
- 상위 계층이 import하는 모듈·예외만 연동 루트에 두고, 인터페이스는 사용하는 레이어 하위(interface/)에 둠 — 루트 인터페이스는 여러 레이어가 공유하는 타입이 생길 때만 만듦
- 단일 클라이언트 클래스 안에 모두 두는 방식과 예외를 전송 계층(client/)에 두는 방식은 기각함
- 연동 인터페이스 파일은 토스 문서 태그 단위(auth, market-data)로 나눔 — API 1종당 1파일 방식은 기각함

## 예외

- 연동 예외는 공통 부모 예외(IntegrationException) 아래 연동별 단일 예외(TossInvestException)만 둠 — 실패 유형은 상태 코드 유무와 응답 본문 에러 코드(error.code)로 구분함, HTTP·타임아웃·네트워크 유형별 하위 예외는 기각함
- 연동 예외는 Nest 예외(HttpException)를 상속하지 않음 — 외부 API의 404 등이 우리 API 응답으로 그대로 노출되지 않게 하고, HTTP 응답 변환은 호출하는 상위 계층이 결정함
- 연동 예외의 요청 헤더·바디는 인증 토큰과 클라이언트 시크릿(client_secret)까지 원문 그대로 담음 — 로컬 프로젝트라 유출 위험이 낮고 에러 파악이 최우선이라 원문 유지함, 로그 외부 전송이나 운영 배포 전에는 마스킹을 먼저 도입해야 함

## 응답 처리

- 연동 계층은 토스 응답을 봉투(envelope)와 소수 문자열(decimal string)까지 원형 그대로 반환하고 변환은 상위 계층 책임으로 둠
- 성공 응답은 런타임 스키마 검증 없이 인터페이스 타입을 신뢰함 — 스키마 검증 라이브러리(zod) 도입은 의존성 추가와 이중 정의로 기각함, 소수 연산 라이브러리(decimal.js)는 상위 계층용으로만 도입함

## 토큰

- 토스 시세 API 메서드는 접근 토큰(accessToken)을 인자로 받고 연동 계층은 토큰을 보관하지 않음 — 발급·보관·갱신은 상위 계층 책임임, 메모리 캐시 방식은 만료 처리 없는 상태 저장과 순환 의존으로 기각함
- 토큰 발급(issueOAuth2Token)은 한 곳에서만 호출해야 함 — 여러 상위 계층이 각자 호출하면 이전 토큰이 무효화될 수 있음, 토스는 클라이언트당 유효 토큰을 1개만 유지함

## 범위와 테스트

- 토스 연동은 토큰 발급과 시세 5종(호가·현재가·체결·상하한가·캔들)만 있음 — 토큰 만료 갱신, 요청 제한 재시도(429 rate limit), 웹소켓(WebSocket) 대응은 아직 없음
- 연동 테스트는 전송 계층과 API 계층(client·api) 단위 테스트만 둠 — 실제 토스 서버를 호출하는 실호출 스모크 테스트는 외부 의존이라 두지 않음
