# 수업 기록과 리포트

## 적용 대상

- 수업 기록·리포트를 제공하고 권한을 강제하는 edu-fit-backend, 시간표 수업 조회 응답을 표시하는 edu-fit-frontend

## 규칙

### 공통

- 학생에게는 수업 기록·리포트 조회 API를 제공하지 않음 — 원장·선생의 내부 산출물임
- 원장은 수업 기록·리포트 전체를 수정·삭제할 수 있음
- 리포트 API는 학생별 최근 리포트 작성일을 제공하지 않음

### 수업 기록

- 수업 기록(LessonNote)은 원장·선생이 수업(Lesson)에 남기는 내부 메모로 수업 1건에 여러 개 둘 수 있고, 학생 수업 응답에는 기록 필드(latestNote)를 싣지 않음
- 원장은 작성자와 무관하게 모든 수업의 기록을 조회·작성·수정·삭제함(GET·POST /api/director/lessons/:lessonId/notes, PATCH·DELETE /api/director/lesson-notes/:noteId)
- 선생은 소속 수업 설정의 teacherId가 본인인 수업에서만 기록을 조회(원장 작성분 포함)·작성함
- 선생의 기록 수정·삭제(PATCH·DELETE /api/teacher/lesson-notes/:noteId)는 본인 작성분만 가능함
- 탐구 업무로만 담당하는 학생의 수업 기록은 선생에게 404임 — 선생 수업 기록 범위는 담당 학생 판정(teacher-scope)을 쓰지 않음
- 선생의 기록 수정·삭제는 범위 밖(타 선생 설정 수업)의 기록이면 작성자가 본인이어도 404 LESSON_NOTE_NOT_FOUND로 존재를 숨김
- 선생의 기록 수정·삭제는 범위 안에서 원장·다른 회원이 쓴 기록일 때만 403 FORBIDDEN이며 판정 순서는 범위 404 → 작성자 403임
- 없거나 삭제된 수업·삭제된 수업 설정의 수업은 기록 목록·작성이 404 LESSON_NOT_FOUND임
- 삭제된 수업·삭제된 수업 설정의 수업에 속한 기록의 수정·삭제는 없는 기록과 같은 404 LESSON_NOTE_NOT_FOUND임
- 수업 소프트 삭제 후에도 기록 행은 남지만 삭제된 수업의 기록을 조회·복구하는 API는 없음
- 수업 기록 목록(GET /api/{director|teacher}/lessons/:lessonId/notes)은 페이지 없이 수업 1건의 기록 전체를 배열로 반환함
- 목록 정렬은 작성 시각 내림차순(같은 초면 ID 내림차순)이고 항목에 작성자(id·name)와 초 단위 UTC createdAt·updatedAt을 실음
- 수업 기록 본문(content)은 1자 이상 UTF-8 65,535 bytes 이하이고 공백만 있는 본문도 저장함
- 본문이 빈 문자열·누락·null·문자열 아님이거나 미정의 필드(authorId 등)가 있으면 400 INVALID_REQUEST임
- 본문의 짝 없는 서로게이트는 500 없이 U+FFFD로 저장됨
- 수업 기록 작성(POST)의 중복 제출 방지는 edu-fit-frontend가 판단함 — edu-fit-backend 작성은 멱등이 아니라 같은 본문을 두 번 보내면 기록 2건이 생김
- 수업 기록 수정은 본문만 바꾸고 작성자·작성 시각을 유지함
- 현재와 같은 본문으로 수정하면 200으로 현재 항목을 반환하되 수정 시각(updatedAt)은 바뀌지 않음
- 수업 기록 삭제는 하드 삭제로 200 data null을 반환함
- 같은 기록의 동시 삭제는 하나만 성공하고 나머지와 재삭제는 404 LESSON_NOTE_NOT_FOUND임
- 원장·선생의 기간 수업 조회·수업 생성·수정 응답의 latestNote는 수업별 최신 기록 1건(작성 시각이 가장 늦고 같은 초면 ID가 큰 기록, 원장 작성분 포함)의 { id, content, author{id,name}, createdAt }임
- latestNote는 기록이 없으면 null이고 수업 생성 응답에서는 항상 null임

### 리포트

- 선생은 담당 학생의 리포트를 작성자와 무관하게 조회·작성하되 수정·삭제는 본인 작성분만 함
- 원장은 전체 학생(비활성 포함)의 리포트를 작성자와 무관하게 조회·작성·수정·삭제함
- 학생 리포트는 원장·선생이 학생 단위로 쓰는 내부 게시글형 산출물이며 학생 토큰의 /api/student/reports는 404 NOT_FOUND임
- 리포트는 상태·임시 저장 없이 저장 즉시 확정되며 삭제는 하드 삭제임
- 선생 리포트 판정 순서는 리포트 존재 → 담당 범위 → 작성자임
- 담당 범위 밖 학생의 리포트는 작성자와 무관하게 없는 리포트와 같은 404 REPORT_NOT_FOUND임
- 선생의 리포트 수정·삭제는 담당 범위 안 타인 작성 리포트일 때만 403 FORBIDDEN임
- 수업 설정 삭제 등으로 담당 범위를 벗어난 학생의 리포트는 선생 본인 작성분이어도 조회·수정·삭제 모두 404 REPORT_NOT_FOUND이며 행은 남음
- 리포트 작성 대상이 선생의 담당 범위 밖 학생이면 학생 조회 없이 404 STUDENT_NOT_FOUND임
- 리포트 작성 대상이 학생 프로필이 없는 회원·없는 ID이면 원장 작성이어도 404 STUDENT_NOT_FOUND임
- 리포트 제목은 코드 포인트 1~255자, 본문은 UTF-8 65,535 bytes 이하임
- 리포트 제목·본문이 공백만 있는 값이면 400 INVALID_REQUEST이며 앞뒤 공백 제거 같은 값 변형은 하지 않음
- 리포트 수정(PATCH)은 전달한 제목·본문만 바꾸고 null은 400임
- 리포트 수정 요청 본문이 빈 객체({})이거나 현재와 같은 값이면 행·수정 시각(updatedAt)을 바꾸지 않음
- 리포트 수정 요청에 대상 학생(studentId)·작성자(authorId)를 보내면 400임 — 대상 학생·작성자는 생성 후 바꾸지 않음
- 원장이 선생 작성 리포트를 수정해도 작성자(authorId)는 원래 작성자로 남음
- 리포트 목록은 작성 시각 내림차순(같은 초면 ID 내림차순)임
- 리포트 목록의 page 1~1,000,000·limit 1~100·studentId 1~4,294,967,295 범위 밖은 400 INVALID_REQUEST임
- 리포트 목록의 studentId 필터가 없는 학생(선생은 담당 범위 밖 학생 포함)이면 404 없이 빈 목록임

## 코드값

원본: `CourseResponseCode` — 일부

| 코드 | 뜻 |
|---|---|
| `LESSON_NOTE_NOT_FOUND` | 404 '존재하지 않는 수업 기록입니다.' — 없는 기록의 수정·삭제에 쓰임 |

## 함정

- 짝 없는 서로게이트가 든 리포트 제목·본문은 작성·수정 응답에 요청 원래 값이, 이후 조회에 U+FFFD가 나옴(의도된 단순화) — 저장 후 행을 다시 읽지 않고 요청 문자열을 그대로 응답함
