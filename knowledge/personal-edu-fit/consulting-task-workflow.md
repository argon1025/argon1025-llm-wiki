# 컨설팅 업무 처리 흐름

## 적용 대상

- 업무 배정·상태 변경·히스토리를 검증하고 저장하는 edu-fit-backend, 배정·상태 변경·산출물 저장 API를 호출하는 edu-fit-frontend

## 규칙

- 업무 상태는 접수·진행 중·완료 3단계이며 접수는 담당자 미배정과 동치임
- 배정 대상은 활성 선생과 원장이며 원장은 본인을 담당자로 지정할 수 있음
- 재배정은 담당자만 바꾸고 상태·산출물·댓글·최초 배정일을 유지함
- 배정 취소는 담당자를 해제하고 접수로 회귀하며 산출물·댓글은 유지됨
- 미배정 업무의 배정 취소·상태 변경은 edu-fit-backend가 거부함 — 접수는 미배정과 동치라 대상 상태가 없음
- 배정 취소·재배정으로 빠진 이전 담당자는 배정 이력 기준으로 해당 업무의 목록·상세를 읽기만 할 수 있고 쓰기는 현재 담당자만 가능함
- 배정·재배정·배정 취소·상태 변경·신청 내용 대리 수정 이력은 시스템 댓글이 아니라 별도 히스토리 테이블에 이벤트 타입과 한국어 문구로 남기는 단순 감사 기록이며 원장·선생이 조회함
- 학생의 요청 철회는 업무를 소프트 삭제하며 산출물·댓글은 보존함
- 산출물은 별도 공유 상태 없이 저장 즉시 학생에게 노출됨
- 원장의 내 업무는 별도 API 없이 원장 업무 목록의 담당자 필터로 조회함
- 숨김은 사용자별 개인 설정이며 목록에만 적용하고 캘린더에는 적용하지 않으며 업무 상태가 아님

## 상태와 전이

- 원장이 담당자를 배정하면 접수에서 진행 중으로 바뀌고 최초 배정일은 비어 있을 때만 기록됨
- 진행 중과 완료 사이 전이는 순서를 강제하지 않고 완료에서 진행 중 회귀를 허용함
- 접수 회귀는 배정 취소로만 도달함

## 절차

- 산출물 저장 후 완료는 edu-fit-frontend가 산출물 저장 API와 상태 변경 API를 순서대로 2회 호출함
