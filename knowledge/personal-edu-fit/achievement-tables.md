# 성취도 표

## 적용 대상

- 표 정의를 교체 저장하고 행 키를 검증하는 edu-fit-backend, 값·정의 제약을 판단하고 추이 그래프를 그리는 edu-fit-frontend

## 규칙

### 권한과 대상 확인

- 성취도 표는 원장(모든 학생)·선생(담당 학생)이 학생별로 생성·수정·삭제하고 학생은 본인 표만 읽기 전용으로 조회함
- 원장·선생의 학생 경로 성취도 API(GET·POST /api/{director|teacher}/students/:studentId/achievement-tables)는 없는 학생·학생이 아닌 회원·학생 프로필 없는 회원이면 조회(GET)도 빈 배열이 아닌 404 STUDENT_NOT_FOUND로 거부함
- 선생이 담당 범위 밖 학생을 성취도 API로 요청하면 없는 대상과 같은 404로 거부해 학생 경로는 STUDENT_NOT_FOUND, 표 경로는 ACHIEVEMENT_TABLE_NOT_FOUND, 행 경로는 ACHIEVEMENT_ROW_NOT_FOUND임

### 표 정의

- 성취도 추이 그래프의 기준 계열 항목 방향이 작을수록 우수(등급·등수·초 기록)면 그래프 축을 역방향으로 표기함
- 성취도 표 정의 수정(PUT)은 표 단위 전체 교체이며, 요청 항목에 기존 항목 ID(items[].id)가 있으면 그 항목을 값과 함께 유지·수정, 없으면 생성하고, 요청에서 빠진 기존 항목은 그 값과 함께 삭제함
- 표 정의 수정에서 items[].id가 그 표의 항목이 아니거나 요청 안에서 중복·null이면 400 INVALID_REQUEST이고, 표 생성 요청의 항목은 id를 받지 않음(보내면 400)
- 성취도 항목 id는 생성 시 부여되는 불변 항목 키라 이름을 바꿔도 유지되고 값이 이 키에 매달림
- 표 생성·정의 수정 요청의 항목(items) 배열 순서가 항목 표시 순서(1부터)임
- 성취도 항목 isDefaultSeries는 추이 그래프 기본 계열 여부임
- 행이 1개 이상 있는 성취도 표의 행 기준(rowType)을 다른 값으로 바꾸면 edu-fit-backend가 409 ACHIEVEMENT_ROW_TYPE_LOCKED로 거부하고, 같은 행 기준이거나 행이 없으면 허용함 — 기존 행의 행 키가 새 행 기준에서 성립하지 않음

### 행

- 학기 축 표에 같은 학기(학교급·학년·학기) 행을 추가하거나 다른 행을 그 학기로 수정하면 edu-fit-backend가 409 ACHIEVEMENT_ROW_DUPLICATED로 거부함 — 학기 축에서 행 위치가 겹쳐 행 키가 성립하지 않음
- 학기 축 중복 판정에서 자기 자신과 같은 학기는 중복으로 보지 않고, 자유 행(FREE)은 같은 라벨도 허용함
- 학기 축(SEMESTER) 같은 학기 행을 동시에 추가하면 하나만 201이고 나머지는 409임
- 성취도 행 요청이 표의 행 기준과 맞지 않는 키를 보내면 edu-fit-backend는 무시하지 않고 어긋난 필드를 모두 담은 400 INVALID_REQUEST로 거부함
- 학기 축(SEMESTER) 표에 학교급·학년·학기를 빠뜨리거나 label을 지정하면, 자유 행(FREE) 표에 label을 빠뜨리거나 학기 키를 지정하면 행 기준과 맞지 않는 키로 400 INVALID_REQUEST임
- 성취도 행 수정(PUT)은 키와 값을 전체 교체해 빠진 항목의 값은 삭제, 남는 항목 값은 갱신, 새 항목 값은 추가함
- 행 수정·추가에서 values[].itemId가 그 표의 항목이 아니거나 요청 안에서 겹치면 400 INVALID_REQUEST이고, 미입력 항목은 응답 values에서 생략됨

### 삭제

- 성취도 표 삭제는 항목·행·값을, 행 삭제는 그 행의 값을 함께 지우고 응답 data는 null이며, 없는 표·행은 404임
- 같은 성취도 표·행의 동시 삭제는 하나만 성공함

### 조회

- 성취도 조회는 목록 오프셋 페이지네이션 규약과 달리 페이지 없이 표 배열 전체를 생성순(id 오름차순)으로 항목(표 정의 요청 순서)·행·값과 함께 반환함(의도된 동작)
- 성취도 조회의 행은 학기 축(SEMESTER)이면 학교급(초등 → 중등 → 고등)·학년·학기 순, 자유 행(FREE)이면 입력 순이며, 행 값은 항목 순서로 담고 값 없는 항목은 생략함
- 성취도 조회 응답 필드는 원장·선생·학생이 같음
- 성취도 표의 createdAt·updatedAt은 초 단위 UTC ISO 8601임
- edu-fit-backend는 학기 축 성취도 표의 행을 학교급과 무관하게 모두 반환하고, 고등만 노출하는 설정은 edu-fit-frontend가 적용함

### 입력 검증

- 성취도 입력이 표 이름·항목 이름·자유 행 라벨 코드 포인트 1~100자(공백만 불가), 단위 50자 이하, 학년 1~255 정수, 학기 1 또는 2를 벗어나면 400이며 앞뒤 공백은 제거하지 않음
- 성취도 값·최소·최대는 유한 double이어야 하며 JSON 1e400처럼 Infinity가 되면 400임
- 성취도 값·범위 검증에서 edu-fit-backend는 숫자 형식과 항목 최소 > 최대(최소·최대가 같거나 한쪽이 null이면 허용)만 거부함
- 성취도 값의 항목 범위 강제, 항목 수 1~8개, 표 이름 중복, 항목 이름 중복, 범위 축소로 인한 기존 값 위반, 학교급별 학년 범위는 edu-fit-backend가 검증하지 않고 edu-fit-frontend가 판단함

## 코드값

### 응답 코드

원본: `AchievementResponseCode` 전 5종

| 코드 | HTTP | 메시지 | 뜻 |
|---|---|---|---|
| `ACHIEVEMENT_TABLE_NOT_FOUND` | 404 | 존재하지 않는 성취도 표입니다. | 선생 API에서 담당 범위 밖 학생의 표도 같은 코드로 숨김 |
| `ACHIEVEMENT_ROW_NOT_FOUND` | 404 | 존재하지 않는 성취도 행입니다. | 선생 API에서 담당 범위 밖 학생의 행도 같은 코드로 숨김 |
| `ACHIEVEMENT_ITEM_RANGE_INVALID` | 400 | 최소값은 최대값보다 클 수 없습니다. | 항목 최소값이 최대값보다 큼 |
| `ACHIEVEMENT_ROW_TYPE_LOCKED` | 409 | 행이 있는 표는 행 기준을 바꿀 수 없습니다. | 행이 1개 이상 있는 표의 행 기준(rowType) 변경 |
| `ACHIEVEMENT_ROW_DUPLICATED` | 409 | 이미 입력된 학기입니다. | 학기 축 표의 같은 학교급·학년·학기 행 추가·수정 |

### 행 기준

원본: `AchievementRowType` 전 2종

| 코드 | 뜻 |
|---|---|
| `SEMESTER` | 학기 축 — 행 키는 학교급·학년·학기이고 라벨은 지정할 수 없음 |
| `FREE` | 자유 행 — 행 키는 라벨(1~100자)이고 학교급·학년·학기는 지정할 수 없으며 입력 순서를 보존함 |

### 항목 방향

원본: `AchievementDirection` 전 2종

| 코드 | 뜻 |
|---|---|
| `LOWER_IS_BETTER` | 작을수록 우수(등급·등수·초 기록) — 추이 그래프 축 방향을 정함 |
| `HIGHER_IS_BETTER` | 클수록 우수 — 추이 그래프 축 방향을 정함 |

## 절차

- 성취도 쓰기 판정 순서는 DTO 형식 400 → 항목 최소 > 최대 400(학생·표 확인보다 먼저) → 대상 학생·표·행 404(선생은 범위 밖 포함) → 요청 값의 표 정합 400(행 키·항목 ID) → 상태 충돌 409임

## 함정

- 학생 본인 조회(GET /api/student/achievement-tables)는 표가 없거나 학생 프로필 없는 계정이면 원장·선생 학생 경로의 404와 달리 빈 배열 200임(정상) — 학생 프로필을 확인하지 않음
- 성취도 표 updatedAt은 표 정의 수정(PUT)마다 값 비교 없이(항목만 바뀐 교체 포함) 갱신되고 행 추가·수정·삭제로는 바뀌지 않음(의도된 동작)
