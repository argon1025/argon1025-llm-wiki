# 탐구 축 관리 화면

## 규칙

- 탐구 축 이름 길이(nameLength, 최대 50자)는 백엔드 varchar(50)와 같은 코드 포인트 단위로 셈 — input maxLength는 UTF-16 단위라 쓰지 않음
- 탐구 축 순서 저장이 400이면 목록을 다시 불러오고, 바꾼 순서(AxisBoard draft)는 병합(편집 중 삭제된 축은 빼고 추가된 축은 맨 뒤에 붙임)으로 유지함 — 다시 저장할 수 있게 함
- 탐구 축 이름 수정·삭제 실패 처리(failWith)는 404(INQUIRY_AXIS_NOT_FOUND)면 이미 삭제된 축으로 보고 토스트 후 목록을 다시 불러오며 모달을 닫음
- 탐구 축 이름 수정·삭제가 404 밖의 이유로 실패하면 모달을 유지함(failWith) — 입력을 지킴
- 탐구 축 순서 저장 성공은 목록 쿼리를 무효화하지 않고 응답 배열을 setQueryData로 넣음 — 무효화 후 재조회로 바꾸면 draft를 비운 순간 재조회 응답 전까지 이전 순서가 한 번 보였다가 바뀜
- 탐구 축 쿼리 키는 공통 활성 목록(active, GET /api/inquiry-axes)과 원장 목록(director)을 같은 접두어(inquiryAxisKeys.all) 아래에 둠 — 원장 변경 뒤 접두어 무효화 한 번으로 활성 목록까지 덮을 수 있음

## 함정

- 탐구 축 드래그 행(CardRow)의 테두리는 ring이 아닌 border로 그림 — ring은 box-shadow라 motion Reorder.Item whileDrag의 boxShadow가 덮어쓰며 드래그 뒤에도 인라인 그림자가 남음
- 탐구 축 순서 변경이 포인터(마우스·터치) 드래그만 지원하는 것은 의도된 동작임
- 저장하지 않은 탐구 축 순서가 있어도 페이지 이탈 경고를 두지 않는 것은 의도된 동작임
