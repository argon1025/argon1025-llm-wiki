# 앱 셸

## 적용 대상

- edu-fit-frontend의 앱 셸(AppShell)과 역할별 사이드바 메뉴(MENUS)

## 규칙

- 화면 이슈는 사이드바 메뉴(MENUS)에 항목을 새로 추가하지 않고, 메뉴 경로마다 이미 있는 페이지에 자기 기능 폴더의 화면 컴포넌트를 배치함
- 앱 셸 사이드바(AppSidebar)는 런칭 1차 메뉴 수(원장 4·선생 2·학생 1)가 아니라 수업·탐구 분석 메뉴가 더해질 최종 네비게이션(와이어프레임 §0.3 기준 원장 10·선생 5·학생 4개)을 담을 수 있어야 함
- 사이드바 메뉴(MENUS) 라벨이 그룹명을 반복하는 것('탐구 컨설팅' 그룹의 '탐구 컨설팅 관리')은 의도된 동작임 — 라벨은 와이어프레임의 그룹명 반복 회피 지침이 아니라 이슈 #10 표를 따름
- 역할별 화면 페이지는 PageHeader와 본문을 감싸는 요소 없이 형제로 반환함 — 앱 셸 panel의 flex gap이 헤더와 본문 사이 간격을 줌
- 사이드바 접힘 상태를 새로고침 뒤에도 유지하려면 SidebarProvider defaultOpen을 document.cookie의 sidebar_state 값으로 정함 — 서버 cookies()로 읽으면 앱 레이아웃이 동적 렌더링으로 바뀜

## 함정

- 사이드바 메뉴가 화면 높이를 넘으면 스크롤 단서 없이 아래 메뉴가 가려짐 — shadcn SidebarContent가 no-scrollbar로 스크롤바를 숨김, 스크롤 단서는 아직 정해지지 않아 수업·탐구 분석 메뉴를 추가하는 이슈에서 정함
- 새로고침하면 사이드바 접힘 상태가 펼침으로 돌아가는 것은 현재 정상 동작임 — SidebarProvider는 접힘 상태를 sidebar_state 쿠키에 쓰기만 하고 읽지 않으며 AppShell은 defaultOpen을 넘기지 않음
