# 역할별 데이터 범위

## 적용 대상

- 권한을 강제하는 edu-fit-backend, 화면에 표시할 값을 조회하는 edu-fit-frontend

## 규칙

- 선생 담당 학생(담당 학생)은 삭제되지 않은 수업 설정의 담당 선생이거나 철회되지 않은 탐구 업무의 현재 담당자(task.assigneeId)가 그 선생인 학생이며(업무 상태는 완료 포함 무관), 학생 단위 선생 API 전부에 같은 정의를 씀
- 재배정·배정 취소로 넘어간 업무만 남은 학생이면 이전 담당 선생의 담당 학생·탐구 분석·학업 성취도·리포트 접근이 범위 밖 학생과 같은 404가 됨 — 넘어간 업무는 담당 근거가 아님
- 재배정·배정 취소로 업무가 넘어가도 같은 학생의 수업 설정 담당(COURSE)이나 다른 현재 담당 업무가 남은 선생은 탐구 분석·학업 성취도·리포트 접근이 유지됨 — 담당 판정은 업무가 아니라 학생 단위임
- 담당 학생에는 비활성 학생과 기간(endDate)이 지난 수업 설정의 학생도 포함함
- 학생은 본인 데이터만 조회하며, 모든 권한·소유권 검증은 서버(edu-fit-backend)가 강제함
- 원장 학생 상세 API는 수업 담당 선생·탐구 담당자를 싣지 않으므로 edu-fit-frontend가 수업 설정 목록·업무 목록의 학생 필터 조회로 표시함 — member 도메인이 course·consulting에 의존하는 것을 피함

## 코드값

원본: `TeacherStudentRelationType` 전 2종

| 코드 | 뜻 |
|---|---|
| `COURSE` | 수업 설정의 담당 선생 |
| `CONSULTING` | 탐구 업무의 현재 담당자 |
