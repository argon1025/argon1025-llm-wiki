# 위키 반영 검토 게이트

## 규칙

- 위키 문서 반영의 품질 게이트는 검토 에이전트가 규약 1~7장을 의미와 형식 모두 읽어 판정하는 것 하나이며 형식 검사 스크립트로 대신하지 않음 — 템플릿만 지켰다고 의미가 맞게 쓰인 것은 아님
- update 검토의 코드 확인 rev는 사실별 check(근거 레포마다 그 레포의 가장 늦은 근거 머지 sha)로 정함 — 레포를 넘는 병합 사실을 문서 단위 하나의 rev로 확인하면 뒤 머지가 거짓으로 만든 사실이 통과함
- 반영 에이전트는 추가·교체한 사실과 같은 식별자를 말하는 기존 문장을 절을 가리지 않고 찾아 함께 참일 수 없으면 같은 편집에서 고치거나 지움 — 조건 표현이 다르다며 별개로 보고 모순 문장을 남기는 경향이 있음
- 반영 에이전트가 기존 문장을 고치거나 지운 사실은 교체로 판정하고 PR 사실 목록 교체 행의 기존 문장(old)으로 리뷰어가 확인함 — 기존 문장의 참인 부분까지 지우는 과삭제가 생길 수 있음
- 검토가 위치 사유로 지운 불릿은 removed의 사실 문장(fact)과 옮길 문서(target)로 재배정 루프(apply.md 4장)에 다시 배정함 — 루프 없이 PR 행으로만 넘기면 위치를 잘못 잡은 사실이 그 PR에 반영되지 않음
- 재배정 루프의 재검토에서도 위치로 지워진 사실은 PR 본문의 제외된 사실 목록에 위치 재배정 행으로 실어 add에 넘김
- 검토의 겹침(한 곳 소유)·위치 판정은 다른 문서가 같은 사실을 가졌는지를 이번 실행 전 내용(git show HEAD)으로만 판단함 — 작업 트리를 읽으면 병렬로 도는 다른 검토가 아직 판정하지 않은 이번 실행 불릿을 근거로 자기 불릿을 겹침으로 지움
- 반영 3장 검토 에이전트의 입력(사실 id·fact, 코드 확인 대상 check, 자료 원문 input)은 assign.json `docs`의 해당 문서 항목을 참조해 받으며 메인이 목록을 조립해 넘기지 않음 — 조립 방식이면 메인이 문서별 지시 파일을 따로 만듦

## 함정

- 같은 머지에 대한 레포 안 사실 판정이 실행마다 달라질 수 있음 — 스크립트 없이 검토 에이전트의 판단만 게이트로 쓰는 대가이며 의도된 동작
