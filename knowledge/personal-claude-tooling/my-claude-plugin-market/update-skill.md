# 위키 update 스킬

## 규칙

- 위키 update 스킬(/agent-wiki:update)은 지정한 도메인 하나(--domain)의 등록 레포 머지만 추출 대상으로 삼음 — 전체 도메인을 한 번에 넣으면 목록이 너무 많아짐
- update 추출 에이전트에는 해당 레포의 현재 지도인 책임(responsibilities)·호스트(hosts)·간선(deps)과 도메인 등록 레포 목록을 함께 넘김 — 넘기지 않으면 간선 대상(to)을 도메인 없이 오기하고 새 기능 단위의 책임 후보를 내지 못함
- update 수집 제외 규칙(EXCLUDE_PATHSPECS)은 `:(exclude,glob)` 형식으로 씀 — glob 매직이 없는 `:(exclude)**/package-lock.json` 형식은 루트 경로의 잠금 파일을 빼지 못해 추출 입력에 담김
- update 한 번에 처리하는 머지 예산(--max-merges) 기본값은 10건 — 머지 1건당 위키 PR 본문과 코멘트가 약 5,600자라 10건이면 GitHub 한도 65,536자 안에 듦
- update 추출 프롬프트는 입력 목록 파일을 한 파일씩 끝까지 읽게 하고 grep·sed 발췌로 대신 읽기를 금지함 — 미열람은 Read 1회 상한(25,000토큰)이 아니라 에이전트 1개의 누적 읽기량에서 생기며 약 19만 토큰에서 발췌로 전환한 사례가 있음
- update는 지정된 머지 범위 안 변경(변경 줄·커밋 메시지·작업 기록이 직접 말하는 상태)만 전사하고 현재 기본 브랜치 코드와의 정합·닫힌 집합 완결·문서 병합은 하지 않음 — 이후 정합은 문서 감사(audit) 몫임
- update 추출은 같은 머지 안에서 커밋 메시지·작업 기록의 값이 변경 줄과 다르면 변경 줄 값만 사실로 남김 — 함께 남기면 같은 API 경로가 코드와 커밋 메시지에서 다르게 나와 사실이 두 건 생김
- update 추출·반영 프롬프트 문장 속에 {domain}/{slug}·{지도} 같은 중괄호 형식 표기를 다시 쓰지 않고 낱말로 가리킴(graph 줄은 '현재 지도의 등록 레포') — 메인이 중괄호를 모두 치환해 다른 값으로 바뀌거나 지도 JSON이 중복 실림

## 함정

- 커서를 최초 커밋으로 둬도 최초 커밋 자체는 반영되지 않음 — update는 커서를 제외한 `{cursor}..origin/{defaultBranch}` first-parent 커밋만 읽음
- update 수집은 커서가 origin/{defaultBranch} first-parent 위에 없는 레포를 skipped로 두고 수집하지 않음 — registry defaultBranch가 기능 PR이 머지되는 브랜치와 다르면 커서 이전 머지를 다시 모으고 릴리스 묶음 머지만 나옴
- update 추출 에이전트는 테스트·생성물 파일을 사실 없음으로 보고 읽지 않고 건너뛸 수 있음 — 추출 응답에서 건너뛴 파일이 있는지 확인

## 결정

- update 추출 에이전트 1회의 입력을 머지 5건 묶음이 아닌 머지 1건(batches())으로 둠 — 실추출 비교에서 재현율이 머지 5건 묶음 0.85, 머지 1건 0.87로 비슷했고, 대가는 토큰이 약 2.3배라는 점
- update 추출은 작업 기록 중심 선별 읽기 대신 머지 diff 전체를 읽음 — 선별 읽기의 재현율이 비슷했던 비교는 모범 답안 사실의 83%가 작업 기록에서 나온 레포였고, 계획·피드백을 남기지 않는 팀원의 레포에서는 작업 기록 중심 읽기가 코드 사실을 놓침
